# Plan de trabajo - lunes 2026-05-04

## Objetivo del dia

Ordenar el arranque de la fase de testing real:

- Vercel como hosting/API para el primer despliegue testeable.
- Supabase como base de datos, Auth y Storage.
- Datos reales del huerto PAC como fuente de aprendizaje.
- Primer caso real: propagacion de matico para Dante.

Hoy no necesitamos automatizar todo. Necesitamos dejar un camino claro, probar por partes y no perder los datos reales que empezaron a aparecer.

## Reglas de foco

- No desplegar hasta que la cuenta/proyecto Vercel este listo y el usuario confirme.
- No cambiar Supabase como base de datos.
- No meter cuidadores completos todavia; solo entender las dos cuentas reales y preparar el test.
- Cada dato real debe quedar como planta, evento, nota o caso documentado.
- El front se mejora desde escenarios reales, no desde suposiciones abstractas.

## Hallazgo Vercel 1

Hora: despues del primer deploy manual en Vercel.

El deploy de `lleken.vercel.app` quedo "Listo", pero el login fallo en navegador con:

```text
Firebase: Error (auth/unauthorized-domain)
```

Interpretacion:

- No es un problema de Supabase como base de datos.
- No conviene resolverlo agregando dominios a Firebase como camino principal.
- El bundle publicado todavia esta usando Firebase Auth.
- El repo local actual ya tiene `AuthContext.tsx` usando Supabase Auth, por lo que Vercel probablemente desplego una rama/commit anterior.

Siguiente accion:

- Revisar en Vercel que rama esta configurada como Production Branch.
- Publicar la rama/commit que contiene la migracion Supabase antes de seguir probando login.
- Repetir smoke test solo despues de confirmar que el bundle publicado ya no carga login Firebase.
